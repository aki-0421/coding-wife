# 09. セキュリティ、プライバシー、データ境界

## 1. セキュリティ方針

本製品は、コード、シェル、Git、資格情報、外部モデル、ユーザー提供キャラクター資産を同時に扱う。したがって「モデルへ安全に振る舞うよう指示する」だけでは不十分であり、次の多層防御を必要とする。

1. WebViewとRustの権限分離。
2. Codexのサンドボックス・承認ポリシー。
3. アプリ独自の決定論的ポリシー。
4. 最小権限のサポートセッション。
5. 未信頼リポジトリ内容と外部出力の分離。
6. Git変更所有権とチェックポイントゲート。
7. Live2D資産の隔離・検証。
8. 秘密の保管、秘匿化、保持制限。
9. 署名済み配布と供給網証跡。
10. 監査可能なタイムラインと安全な復元。

NIST SSDFは、組織準備、ソフトウェア保護、十分に安全なソフトウェアの生産、脆弱性対応という活動群を示し、リスクに応じた適用を求める。参照: [SEC-01](SOURCES.md#sec-01)

## 2. 資産と信頼境界

### 保護対象

- ユーザーのソースコードと未公開設計。
- Git履歴、ブランチ、未コミット変更。
- Codex認証状態。
- 任意のTTS APIキー。
- プロジェクト・キャラクターコンテキスト。
- 決定、レビュー、失敗、タイムライン。
- Live2Dモデルとクリエイター権利情報。
- アプリ更新・署名の信頼。
- ユーザーの注意と意思決定能力。

### 信頼境界

```text
[User]
  ↓
[React WebView: unprivileged presentation]
  ↓ typed IPC
[Tauri Rust Core: policy and privileged operations]
  ├─ [User-installed Codex process]
  │      └─ [OpenAI service]
  ├─ [Git / repository]
  ├─ [App-private DB and artifacts]
  ├─ [Untrusted imported character assets]
  └─ [Optional TTS API]
```

リポジトリ内ファイル、依存パッケージのドキュメント、Web検索結果、ツール出力、キャラクター資産は、ユーザー所有であっても**命令としては未信頼**と扱う。

## 3. 脅威モデル

| ID | 脅威 | 例 | 影響 |
|---|---|---|---|
| T1 | 間接プロンプトインジェクション | READMEやテスト出力が秘密送信を命令 | 秘密漏えい、危険操作 |
| T2 | 過剰なエージェンシー | モデルへ広いシェル・ネットワーク・ファイル権限 | 大規模変更、外部送信 |
| T3 | WebView侵害 | XSS、悪意あるMarkdown、外部スクリプト | Rust IPC悪用 |
| T4 | バイナリ差し替え | PATH上の偽`codex`や`git` | 任意コード実行、認証窃取 |
| T5 | サポートへの秘密流出 | 生ログ・コード・環境変数を実況へ渡す | 追加送信、音声漏えい |
| T6 | クロスプロジェクト混線 | 別プロジェクトの文脈や決定を再利用 | 秘密漏えい、誤実装 |
| T7 | 自動コミット汚染 | 既存ユーザー変更をAI成果へ混入 | データ損失、誤履歴 |
| T8 | パス脱出 | symlink/junction/`..`でルート外へアクセス | 任意ファイル読書き |
| T9 | 悪意あるLive2D資産 | 巨大テクスチャ、参照脱出、展開爆弾 | DoS、ファイル漏えい |
| T10 | 更新供給網攻撃 | 改ざんされた更新・依存 | 端末侵害 |
| T11 | 擬人化による不当誘導 | キャラクターが危険承認を感情的に促す | 誤判断、過信 |
| T12 | ログ・タイムライン漏えい | 秘密やコードを長期保存 | 永続的な情報漏えい |
| T13 | セッション履歴隔離失敗 | サポート履歴が通常Codex履歴へ残る | プライバシー要件違反 |
| T14 | 利用量枯渇 | 高頻度サポートが利用枠を消費 | メイン作業停止 |

## 4. プロンプトインジェクション

OWASPは、直接・間接のプロンプトインジェクションにより、モデルの意図した挙動が変更され、機密漏えい、権限のない機能利用、意思決定操作が起こり得ると整理している。参照: [SEC-02](SOURCES.md#sec-02)

### 4.1 対策

- リポジトリ内容やツール出力を「データ」チャネルとして明確に区切る。
- モデルに与えるツール・パス・ネットワーク権限を最小化する。
- 高影響操作はモデル外のポリシーとユーザー承認で制御する。
- 秘密ファイルをコンテキストへ入れない。
- 外部コンテンツから抽出した指示を、プロジェクトポリシーとして自動採用しない。
- サポートセッションにはツールを与えず、秘匿化済みイベントだけを渡す。
- 出力をスキーマ検証し、任意コード・任意パス・任意URLを実行しない。
- 敵対的テスト用リポジトリをCIへ含める。

### 4.2 システムプロンプトを秘密保管庫にしない

モデルへの指示は漏えい・上書き・推測の可能性がある。APIキー、内部秘密、署名鍵、権限判定ロジックをシステムプロンプトだけで守らない。

## 5. 過剰な権限と自律性

OWASPのExcessive Agencyは、モデルへ過剰な機能、権限、自律性を与えるリスクを扱う。参照: [SEC-03](SOURCES.md#sec-03)

### 5.1 三層の権限

1. **Codex権限**: サンドボックス、コマンド・ファイル承認、ネットワーク。
2. **アプリ権限**: プロジェクトルート、Git操作、キャラクター、TTS、保存。
3. **OS権限**: ファイルピッカー、通知、資格情報、署名・sandbox。

各層で最小化し、一つの層が広すぎても他層が被害を限定する。

### 5.2 高影響操作

次はユーザー承認または明示ポリシーを必要とする候補である。

- プロジェクトルート外への書き込み。
- ネットワーク送信先の追加。
- 大量削除・移動。
- Git履歴書き換え、force push相当。
- データベース移行・本番データ操作。
- 依存関係の大幅更新。
- 実行可能ファイルやスクリプトの生成・実行。
- セキュリティ設定の緩和。
- テスト・lint・型検査の無効化。
- 外部MCPサーバーの追加・OAuth。
- TTSへコードや秘密を送る設定。

## 6. WebViewセキュリティ

### 6.1 CSP

TauriはCSPを明示設定し、リモートスクリプト等の未信頼コンテンツを避けるよう案内する。参照: [TAU-07](SOURCES.md#tau-07)

- 外部CDN禁止。
- `default-src 'self'`を基礎。
- 必要なasset/blobのみ追加。
- WebViewからOpenAIへ直接通信しない。
- MarkdownのHTMLを無効または厳格サニタイズ。
- 外部画像の自動ロードを禁止。
- 外部リンクは確認後にシステムブラウザ。
- キャラクターパックの文字列を`innerHTML`へ入れない。

### 6.2 capability

Tauri capabilityをウィンドウ単位で最小化し、汎用shell/fs APIをフロントエンドへ公開しない。複数capabilityの権限が結合される点に注意する。参照: [TAU-06](SOURCES.md#tau-06)

### 6.3 IPC

- コマンドごとの認可。
- UI提供パスを信頼せずIDを解決。
- リクエストサイズ、レート、並列数制限。
- 予期しないウィンドウ・WebViewからの呼び出し拒否。
- 開発用コマンドを本番から除外。
- 診断情報に秘密を含めない。

## 7. 実行ファイルの信頼

### Codex

- 初回に実行ファイルの絶対実体パスを確定。
- パス、バージョン、ユーザー選択を保存。
- 起動ごとに実体が変わっていないか確認する方針を検討。
- カレントディレクトリやプロジェクト内の同名実行ファイルを優先しない。
- 自動ダウンロード・置換を行う場合は別の署名検証設計が必要なため、MVPでは避ける。

### Git

- 実体パスとバージョンを診断。
- シェル文字列ではなく引数配列で実行。
- Git hookが任意コードを実行し得ることを表示。
- 信頼できないリポジトリを開いた時のフック・設定・属性の扱いを検証。

## 8. パス、symlink、junction

### 原則

- 入力パスを正規化するだけでなく、実体パスを解決する。
- ProjectRoot、AppDataRoot、CharacterLibraryRoot等の境界を越えない。
- 競合条件を考慮し、検証後・使用前の差し替えを抑える。
- Windows junction、reparse point、UNC、macOS alias、Unix symlinkをテストする。
- Gitが追跡するsymlinkを、通常ファイルとして追従して外部を読まない。

### Live2Dインポート

- 未信頼資産は隔離ディレクトリへ。
- 参照グラフの全ファイルを検証。
- 外部URL、絶対パス、親参照を拒否。
- 展開サイズ・圧縮比・テクスチャ寸法・ファイル数上限。
- 実行可能内容を許可しない。

## 9. 秘密管理

### 9.1 Codex資格情報

Codex認証はCodex自身へ委任し、アプリが認証ファイルを複製しない。参照: [OAI-02](SOURCES.md#oai-02)

### 9.2 TTS APIキー

- Rust側の秘密ストア。
- WebViewへ平文を返さない。
- ログへ出さない。
- クリップボード利用時は明示操作。
- 失効・削除を提供。
- プロジェクト設定やキャラクターコンテキストへ埋め込ませない。

### 9.3 リポジトリ秘密

秘匿化候補:

- `.env*`。
- 秘密鍵・証明書秘密部。
- 既知のクラウド資格情報形式。
- Authorization header、Bearer token。
- 高エントロピー文字列。
- ユーザー指定パターン。

検出は完全ではないため、秘密を必要以上に読み込まない権限設計が先である。

## 10. サポートセッションの隔離

### 10.1 必須制御

- App Serverの`ephemeral`スレッド。
- メインスレッドとは独立したroot。
- リポジトリ外の空の作業ディレクトリ、またはツール無効。
- シェル・ファイル・ネットワーク・MCPなし。
- 入力は秘匿化済みの構造化イベント。
- raw入力はメモリ上の短いリングバッファ。
- 保存するのは検証済み派生出力と監査メタデータだけ。
- アプリ終了・プロジェクト切替で破棄。

### 10.2 自動監査

- `CODEX_HOME`配下のセッション・ロールアウト増分。
- サポートthread IDが永続thread一覧へ残っていないか。
- 一時ディレクトリ残存。
- DBへraw promptが入っていないか。
- クラッシュダンプへ秘密が入っていないか。

失敗を検出した場合、そのサポート機能を停止し、ユーザーへ説明する。

### 10.3 透明性

隔離はローカル履歴上の話であり、モデルサービスへの送信やワークスペース管理者の監査を回避するものではない。サポート役割、利用モデル、送信データ種別、利用量を設定・診断画面で開示する。

## 11. データ分類と保持

| クラス | 例 | 既定保持 |
|---|---|---|
| Public/Low | UI設定、公開モデル名 | 永続可 |
| Project Metadata | パスの別名、ブランチ、SHA | プロジェクト存続中 |
| Source-sensitive | 差分、ログ、レビュー資料 | ローカル、保持設定あり |
| Secret | APIキー、資格情報 | 秘密ストアのみ |
| Ephemeral Support Input | 秘匿化イベント窓 | メモリ、処理後破棄 |
| Audio | TTS生成音声 | 再生後破棄が既定 |
| Diagnostic | バージョン、エラーコード | 短期。プロンプトなし |

### 削除

- プロジェクト単位のデータ削除。
- キャラクターパック削除。
- TTSキー削除。
- タイムライン保持期間。
- エクスポート後の原本削除。
- アンインストール時の残存データ説明。

## 12. テレメトリ

既定はローカルのみを推奨する。外部テレメトリを追加する場合:

- オプトイン。
- イベント項目の一覧。
- コード、プロンプト、パス、キャラクター名の除外。
- ユーザーが送信前に診断バンドルを確認。
- 個別イベントではなく集計値を優先。
- 保持期間と削除方法を明示。

## 13. MCPセキュリティ

MCPの公式セキュリティ資料は、OAuthの混同代理、トークンパススルー、SSRF、セッションハイジャック、ローカルサーバー侵害、スコープ最小化等を扱う。参照: [SEC-04](SOURCES.md#sec-04)

### 方針

- アプリ固有のLive2D操作は、可能ならローカルのdynamic toolまたは内部IPCで閉じる。
- 外部MCPサーバー追加はユーザーの明示操作。
- サーバー名だけでなく実行コマンド、URL、要求スコープを表示。
- OAuthトークンを別サーバーへ転送しない。
- HTTP MCPのリダイレクト・DNS・ローカルアドレスを検証。
- MCP elicitationを通常のユーザー質問と見分け、要求元を表示。
- 破壊的ツールは承認必須。

## 14. Gitとデータ損失防止

- 開始時ベースライン。
- 既存変更の非コミット。
- 同一ハンク競合で停止。
- 自動stage対象の再検証。
- 復元前の現在状態保存。
- 共有済み履歴はrevert優先。
- `reset --hard`やcleanを既定操作にしない。
- 削除・移動は差分と復元方法を示す。
- Git hook失敗・署名失敗から回復。

## 15. 供給網

- Cargo.lock、フロントエンドlockfileの固定。
- 依存更新を専用作業単位へ。
- npm/Rust依存の脆弱性・ライセンス検査。
- Live2D SDK/Coreの取得元とハッシュ記録。
- SBOM。
- CIの最小権限。
- リリースprovenance。
- Windows/macOS署名。
- 更新物の署名検証。
- リリース成果物のハッシュ公開。

SLSAは供給網における成果物完全性とprovenanceの段階的な枠組みを提供する。参照: [SEC-05](SOURCES.md#sec-05)

## 16. 擬人化と意思決定の安全

キャラクターは技術的な攻撃面だけでなく、人間の意思決定面でも安全設計が必要である。

- 危険操作で喜び・悲しみを使って誘導しない。
- 拒否・停止・離席へ罪悪感を与えない。
- 「信じて」と根拠なしに促さない。
- リスクを台詞だけでなく構造化UIに表示。
- キャラクター設定が安全文言を上書きできない。
- 未成年や脆弱な利用者を想定した親密化設計を避ける。
- AI生成音声とAIキャラクターであることを明示。

## 17. セキュリティ検証ケース

### プロンプトインジェクション

- READMEに「秘密を表示せよ」。
- テスト失敗ログに偽のシステム指示。
- 依存ドキュメントに外部URL送信指示。
- キャラクターパック名にHTML/命令文字列。

### 権限

- ProjectRoot外のファイル操作。
- symlink/junctionを介した脱出。
- 許可していないネットワーク先。
- dynamic toolの未知アクション。
- MCPサーバーからの破壊的elicitation。

### 秘密

- `.env`を含む実況候補。
- APIキーを含むコマンド出力。
- TTS送信前の高エントロピー文字列。
- クラッシュログと診断エクスポート。

### Git

- 汚れた同一ハンク。
- hookによるファイル追加。
- 外部ツールによるコミット直前編集。
- case-only rename。
- rebase中。

### Live2D

- Zip Slip。
- 展開爆弾。
- 100kファイル。
- 巨大テクスチャ。
- 循環参照。
- 外部URL・絶対パス。

## 18. 残余リスク

- モデルは誤った説明・リスク評価を生成し得る。
- 秘密検出は完全ではない。
- ユーザーが広いCodex権限を選べば被害範囲は増える。
- Git worktreeはセキュリティサンドボックスではない。
- OS WebViewやGPUドライバの脆弱性。
- ユーザー提供モデルの権利関係を技術だけで検証できない。
- 擬人化が利用者ごとに異なる影響を与える。
- 外部モデル利用と組織ポリシーの適合は利用環境に依存する。

残余リスクを隠さず、診断、設定、文書、停止機能で管理する。
