# AIコーディング・コンパニオンエディター 調査資料

- 調査基準日: 2026-07-16（JST）
- 対象: Tauri（Rust）+ React + TypeScript + Viteによるローカルデスクトップアプリ
- 位置づけ: 要件定義前の成立性・設計選択肢・リスク・検証課題の整理

## 調査の問い

本調査は、次の問いに答えるために行った。

1. ユーザーの既存Codex CLI認証とサブスクリプションを再利用し、独自のチャットクライアントを安全に構築できるか。
2. メインのコーディングセッションと、画面演出・説明・レビューを担うサポートセッションを分離できるか。
3. Live2Dキャラクターを、単なる装飾ではなく「状況理解・意思決定・レビュー」を助ける情報チャネルとして成立させられるか。
4. 大量のAI生成コードに対し、品質・レビュー可能性・開発速度のトレードオフをどのように再設計できるか。
5. Windows、macOS、Linuxで、プロセス制御・WebGL・Git・権限・署名を含む現実的な配布が可能か。

## エグゼクティブサマリー

### 1. 技術的な中核は成立する

Codexとの統合には、端末画面や標準出力の見た目を解析する方式ではなく、公式の**Codex App Server**を使用するべきである。App Serverは、認証、会話履歴、承認要求、計画、コマンド、ファイル変更、差分、レビュー、ストリーミングイベントを双方向プロトコルで提供する。これにより、チャット、構造化された意思決定、進捗タイムライン、レビュー画面を一貫したイベントモデルで構築できる。`stdio`のJSONL接続をRust側で管理する構成が第一候補である。参照: [OAI-01](SOURCES.md#oai-01)

### 2. 既存サブスクリプションは再利用できるが、認証情報をアプリへコピーしてはいけない

Codex CLIはChatGPTサインインによるサブスクリプション利用とAPIキー利用の両方をサポートする。アプリはユーザーが既にログイン済みのCodexプロセスを起動し、その認証ライフサイクルをCodex側に任せる。`auth.json`やトークンを独自DBへ複製しない。読み上げは外部provider/keyを追加せず、default offのmacOS local speech adapterへ限定する。参照: [OAI-02](SOURCES.md#oai-02)、[TAU-09](SOURCES.md#tau-09)、[macOS local narration実測](macos-local-narration-runtime.md)

### 3. メインモデル固定とサポートモデル選択は両立する

メインセッションは`gpt-5.6-sol`へ固定し、UIにモデル選択を置かず、利用可能な思考レベルだけを公式の`model/list`結果から表示する。サポートセッションはGPT-5.6ファミリーだけに限定し、短い状態分類・実況にはLuna、要約・説明にはTerra、高リスクレビューにはSolを割り当てる。ただし、この割り当ては性能・待ち時間・利用量の実測後に調整すべき仮説である。参照: [OAI-01](SOURCES.md#oai-01)、[OAI-03](SOURCES.md#oai-03)、[OAI-04](SOURCES.md#oai-04)

### 4. サポートセッションは「サブエージェント」ではなく、独立した一時スレッドにする

メインセッションから生成される通常のサブエージェントは、コーディング作業の一部としてそのまま許可する。一方、実況、状態推定、意思決定説明、コミット解説などは、メインスレッドの子エージェントにせず、App Server上の独立した`ephemeral`スレッドとして起動する。サポートスレッドにはリポジトリやシェルを直接渡さず、正規化・秘匿化したイベントだけを入力する。これにより、通常のCodexセッション履歴へロールアウトファイルを残さない設計が可能になる。なお、モデル呼び出し自体はOpenAI側へ送信され、利用枠を消費するため、その点をユーザーから隠してはならない。参照: [OAI-01](SOURCES.md#oai-01)

### 5. 構造化質問は実現可能だが、実験的APIへの依存を隔離する

App Serverには、短い質問と選択肢を送る`tool/requestUserInput`、アプリ固有の動的ツール、MCP elicitationがある。ただし一部は実験的である。製品内部では`request_user_decision`という安定した抽象インターフェースを定義し、実行時の機能検出により、ネイティブ質問、動的ツール、通常チャットの順にフォールバックする。参照: [OAI-01](SOURCES.md#oai-01)、[OAI-06](SOURCES.md#oai-06)

### 6. 品質問題の解決には、Gitだけでなく追記型タイムラインが必要である

Gitコミットはレビュー境界と復元点として優れているが、失敗した試行、途中の判断、却下した選択肢、検証証拠を完全には表現しない。したがって、各作業単位を「調査→設計→実装→検証→修正→チェックポイント」の状態機械として管理し、Gitコミットと、アプリ専用の追記型タイムラインDBを対応付ける。Git reflogは期限切れするローカル履歴であり、製品の監査タイムラインの正本には向かない。Git notesは任意のエクスポート先としては使えるが、正本にはしない。参照: [GIT-01](SOURCES.md#git-01)、[GIT-02](SOURCES.md#git-02)、[GIT-03](SOURCES.md#git-03)

### 7. Live2Dのユーザーモデル読み込みは重大な公開ゲートである

任意数のユーザーモデルを追加できるアプリは、Live2Dのライセンス上「Expandable Application」に該当する可能性が高い。公式説明では、規模を問わず公開前審査と特別な公開ライセンス契約が必要で、承認されない可能性もある。SDK利用許諾と、同梱キャラクターのクリエイター許諾は別問題である。MVPでは同梱モデルだけで成立させ、ユーザーインポートは書面確認を得るまで配布ビルドで無効化できる構造にする。この記述は法的助言ではなく、公開前に権利者へ確認が必要である。参照: [L2D-01](SOURCES.md#l2d-01)、[L2D-02](SOURCES.md#l2d-02)

### 8. キャラクターの感情は「事実」ではなく、演出上の状態推定として扱う

キャラクターが擬人化されるほど、親しみや継続利用には寄与し得る一方、能力や確信への過信を誘発し得る。表情は、進捗、注意、リスク、不確実性、待機などの運用状態を補助的に表す。必ず同じ情報をテキスト、アイコン、テスト結果でも提示し、キャラクターだけを信頼判断の根拠にしない。表情には有効期限と根拠イベントを持たせる。参照: [HCI-01](SOURCES.md#hci-01)、[HCI-04](SOURCES.md#hci-04)、[HCI-06](SOURCES.md#hci-06)

### 9. 「クロスプラットフォーム」は単一ホストからの万能クロスコンパイルではなく、同一コードベース＋ネイティブCIマトリクスと捉える

TauriはWindows、macOS、Linuxを同一コードベースで扱えるが、各OSのWebView、SDK、署名、パッケージング要件は異なる。WindowsはWebView2、macOSはWKWebView、LinuxはWebKitGTKであり、Live2D/WebGLの互換性を実機で検証する必要がある。リリースビルドは各OSのネイティブランナーで生成し、署名・公証まで自動化する。参照: [TAU-01](SOURCES.md#tau-01)、[TAU-02](SOURCES.md#tau-02)、[TAU-10](SOURCES.md#tau-10)

### 10. 最初の価値検証は、機能数ではなく「理解とレビューの改善」で測る

成功指標は生成コード量ではない。構造化意思決定により選択肢理解時間が短くなったか、チェックポイントによりレビュー漏れと差し戻し時間が減ったか、ユーザーが現在地・未解決リスク・次工程を正しく説明できるか、キャラクター表現が過信ではなく適切な注意を促したかを測る。AIコードレビュー研究では、人間の文脈理解と検証が依然重要で、冗長なAIフィードバックが認知負荷を増やす場合も報告されている。参照: [HCI-02](SOURCES.md#hci-02)、[HCI-03](SOURCES.md#hci-03)

## エビデンス表記

各資料では、次のラベルを使う。

- **確認済み**: 公式ドキュメント、標準、一次資料で直接確認できる事実。
- **設計推論**: 確認済み事実を組み合わせた、本製品向けの設計判断。
- **仮説**: 実測・ユーザーテスト・ベンチマークが必要な案。
- **公開ゲート**: 解消するまで一般配布へ進めるべきでない事項。

## 最優先の公開ゲート

1. Live2D SDKとユーザーモデル追加機能の公開ライセンス確認。
2. 対応するCodex CLI最小バージョンと、実験的App Server機能のフォールバック検証。
3. `ephemeral`サポートセッションが通常の履歴ファイルを生成しないことの自動監査。
4. main Codex のcommit skill注入と既存の未コミット変更を保護する運用、およびnative Git observerがread-onlyであることの検証。
5. Windows、macOS、LinuxそれぞれのWebGL、入力、GPU負荷、プロセス終了、署名済み配布検証。
6. キャラクター表現がリスクを矮小化したり、ユーザーを急かしたりしないことのUX評価。

## 調査上の注意

- OpenAI、Codex、モデル、SDK、Tauriの仕様は更新される。要件確定時とリリース前に再確認する。
- 実験的APIは内部アダプターの背後に置き、UIやドメインモデルを直接依存させない。
- ライセンスに関する整理は技術調査の範囲であり、法的判断ではない。
- 公開UIから得た知見は、レイアウト・情報階層・ワークフローという一般原則へ抽象化している。名称、固有表現、ビジュアル資産、コピーは転用しない。
