# デスクトップ共通仕様

この文書は複数画面に共通するデスクトップ動作の正本である。未確定の項目は空欄にせず、末尾の「未確定事項」で管理する。

## 技術上の前提

- UIはTauriのWebView上でNext.jsを動作させる。
- 標準構成ではNext.jsの静的出力（`output: "export"`）をTauriへバンドルする。
- アプリ内でNext.jsサーバーが動作することを前提にしない。
- 実行時サーバーを必要とするSSRやServer Actionsへ、デスクトップ固有処理を依存させない。
- ローカルOS操作はTauri CommandまたはTauri plugin、オンライン処理は明示した外部APIを境界とする。
- sidecarまたはローカルサーバーを導入する場合は、採用理由、配布、起動、終了、障害時動作、セキュリティ境界を別途決定する。

参考: [Tauri公式 Next.jsガイド](https://v2.tauri.app/start/frontend/nextjs/)

## ウィンドウ設計

Tauri window labelはWindow / WebViewを参照する実行時識別子であり、画面IDではない。CapabilityはwindowまたはWebViewのlabelへ付与されるため、labelをセキュリティ境界として扱う。

参考: [Tauri公式 Capabilities](https://v2.tauri.app/security/capabilities/)

### window labelの規則

- 固定ウィンドウは、役割を表す小文字のkebab-caseで命名する。
- titleや画面名をwindow labelとして使わない。
- 同じ役割のウィンドウを再生成しても、固定ウィンドウのlabelは変更しない。
- 動的labelが必要な場合は、生成規則、重複時動作、Capabilityの適用範囲を明記する。
- 画面が増えたことだけを理由にウィンドウを増やさない。独立したライフサイクルまたは権限境界が必要な場合に追加する。

### ウィンドウ台帳

| window label | 目的 | 初期画面ID | 生成契機 | 多重起動 | 閉じる操作 | Capability |
|---|---|---|---|---|---|---|
| `<label>` | `<目的>` | `<S-NNN>` | `<契機>` | `<許可 / 再利用 / 拒否>` | `<破棄 / 非表示 / アプリ終了>` | `<identifier>` |

ウィンドウ構成が確定したらプレースホルダ行を実値へ置き換える。

## Capabilityと認可

- Capabilityは必要最小限とし、実際の設定は `src-tauri/capabilities/` を正本とする。
- 各ウィンドウへ付与するCapability identifierを「ウィンドウ台帳」に記録する。
- 個別画面仕様には、その画面が必要とするネイティブ操作と、拒否・失敗時のユーザー向け動作を書く。
- 画面IDやNext.js path / view keyをCapability境界として扱わない。
- 同じwindow label内の画面で異なる認可が必要な場合は、Rust側で認可するか、別ウィンドウ境界に分離する。
- ファイルアクセス等のscopeは、必要なパスと操作だけに限定する。

| window label | Capability identifier | 許可する操作 | 許可scope | 設定ファイル |
|---|---|---|---|---|
| `<label>` | `<identifier>` | `<操作>` | `<scope>` | `src-tauri/capabilities/<file>` |
